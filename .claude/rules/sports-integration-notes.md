# Sports integration notes

*Last touched 2026-09-25. Which additional team sports were investigated for `espnTeamSportService`/`cricketService`, and why some didn't make the cut.*

Investigated on 2026-09-16 while adding NRL and WNBA (both shipped — see `CLAUDE.md` for the code-level quirks: NRL's id-keyed logo CDN, its scoreboard endpoint rejecting date ranges, its lack of ESPN colour data).

**MLS — not shipped, don't re-add without re-checking first.** ESPN's site API has real MLS team data (`soccer/usa.1`) and even a genuine numeric-id-keyed logo scheme matching NRL's pattern. But its `/standings` endpoint returned a genuinely empty response (`{}`, no `fullViewLink` wrapper even) when checked directly — a different failure from NRL/AFL/WNBA's "empty right now" shape (which do return the `fullViewLink`-only structure the app's `flattenStandingsEntries` already tolerates). Whether that's permanent or a temporary ESPN quirk for that competition wasn't determined. Re-verify the standings endpoint directly before trying again.

**Rugby union — not investigated in depth.** ESPN's core API lists 25+ separate rugby union competitions (Six Nations, Rugby Championship, URC, Premiership Rugby, etc.) with no single obvious "the" league the way NRL has exactly one. Would need a decision on which specific competition(s) to add, not just a slug lookup.

**F1 — technically has ESPN "team" data (constructors), but doesn't fit the app's data model.** No opponent, no win/loss record — just a points table and a race calendar. Would need a genuinely different card type, not a config addition.

**Update 2026-09-17 — more candidates checked, plus a universal bug found along the way:**

While researching further additions, found that ESPN's `/scoreboard?dates=X-Y` range query started 400ing for *every* league (NFL/AFL/NHL/MLB/NRL alike) — not an NRL-specific quirk as first thought. This was live-broken in production at the time (silently emptying the Today feed / league overview for every ESPN-routed league) and was fixed same-day by dropping the date param entirely everywhere (commit `260e35a`). If a future add hits this again, check whether ESPN restored range support before reintroducing per-league special-casing.

**NWSL and A-League — shipped 2026-09-18** (commit `4854125`). Same id-keyed logo mechanism NRL introduced, both have real ESPN colour data (unlike NRL, so no `teamColors.js` fallback needed), both confirmed live end-to-end (real results, real logos, real fixtures) before pushing.

**Liga MX and Brasileirão — shipped 2026-09-19** (commit `9ece64f`). Same pipeline, this time with the scoreboard/schedule endpoints actually checked up front (both healthy) rather than left as a known gap. Confirmed live: América's and Flamengo's real results, correct logos, real fixtures from both scoreboards.

**Argentina (Liga Profesional), Saudi Pro League, and Primeira Liga — shipped 2026-09-20** (commit `c34d47c`), plus 4 other national leagues verified viable but not shipped (Turkey, Scotland, Japan, Belgium — user chose "2-3 biggest names" over all 7). Argentina's roster (30 teams, the biggest yet) has a real data quirk worth knowing about: ESPN's own data has two different clubs sharing the literal abbreviation "RIV" (Independiente Rivadavia and River Plate). Resolved by routing Independiente Rivadavia through abbreviation matching (it happens to be the first "RIV" in ESPN's own list, so this resolves to itself) and forcing River Plate through the existing name-based fallback instead (safe for "River Plate" — no other club's name collides with it). Verified live: all three of River Plate, Independiente Rivadavia, and plain "Independiente" (a *third*, separate club whose name is a literal substring of Independiente Rivadavia's) resolved to their own correct, distinct real results — this is the kind of collision worth checking for by hand in any large single-country roster, not just trusting the general abbreviation/name fallback to sort itself out.

At this point every soccer-shaped ESPN league checked so far has shipped cleanly — the remaining unshipped candidates below are all disqualified for structural reasons (bad standings data, no matching league, wrong data shape), not because they weren't gotten to yet.

**Turkish Süper Lig and Scottish Premiership — shipped 2026-09-21** (commit `d9a0744`). Scotland's roster forced a real fix, not just a workaround: ESPN's own data has two clubs sharing the abbreviation "DUN" (Dundee, Dundee United), and unlike Argentina's case there's no abbreviation-only escape hatch — any "DUN"-equal abbreviation resolves to whichever team ESPN lists first regardless of which is meant, and "Dundee" is a genuine substring of "Dundee United"'s own name. Fixed **in the shared `findTeamByName()` matching function itself** (not a per-league workaround): it now checks every team for an exact name match before ever trying a fuzzy substring one. This is a general improvement, not Scotland-specific — retroactively also covers Argentina's Independiente/Independiente Rivadavia case via the same mechanism. Verified live: Dundee and Dundee United each resolved to their own correct, distinct real results.

**Lesson for any future large or single-country roster:** always scan for two things by hand before shipping — (1) two teams sharing the same ESPN abbreviation, and (2) one team's name being a literal substring of another's (e.g. "Dundee" inside "Dundee United", "Independiente" inside "Independiente Rivadavia"). Case (1) alone is solvable per-team (River Plate model); case (2) combined with (1) needs the exact-match-first fix already in place, not another workaround.

Still-viable-but-unshipped soccer leagues: none left from the 2026-09-20 batch — J1 shipped 2026-09-24 and Belgium 2026-09-25 (see below).

**IPL and Big Bash League — shipped 2026-09-22** (commit `318572b`), via a genuinely new provider, not ESPN. Re-checked the cricket dead-end from 2026-09-16 properly this time (direct site-API slug probes, ESPN's core API cricket league list re-confirmed empty, ESPNcricinfo's own backend returns 403 to unauthenticated requests) before concluding ESPN really has nothing here. Went with **cricketdata.org** (formerly CricAPI) instead — free tier, 100 requests/day, real IPL/BBL data confirmed live before building anything (`series`, `series_info`, `series_points` all real and working). See `CLAUDE.md` for the code-level architecture (new `services/cricketService.js`, `CRICKET_API_KEY` env var, `SERIES_IDS` needing a yearly manual refresh, no numeric score available, no colour data). Key operational notes not in CLAUDE.md:
- **`CRICKET_API_KEY` is NOT hard-required in production** by `validateEnv.js` — matches `FOOTBALL_API_KEY`/`BASKETBALL_API_KEY`'s convention (sport-data keys degrade to "unavailable" gracefully, unlike `RESEND_API_KEY`/`INTERNAL_REFRESH_SECRET` which crash the server if missing). So this push carried no crash-loop risk, unlike some earlier ones this week — but the key still needs setting on Render for IPL/BBL to actually work live, just not urgently.
- **Whole day of research + build + live smoke-testing used only 23 of the 100 daily hits** — the 3h cache TTLs should keep steady-state production usage well within budget; no need to panic-tighten caching further unless real usage patterns say otherwise.
- **BBL's 2026-27 series has no fixtures/squads yet** (season starts December) — team roster was sourced from the most recently *completed* season (2025-26) instead, since the 8 franchises are stable year to year even when the current season's data is empty. Expected to self-resolve once cricketdata.org populates the new season's fixtures closer to December; nothing to fix, just don't be alarmed if BBL shows no live data for a few months.
- Also fixed a real pre-existing bug found while touching `LeagueCard.jsx`: every league shipped since NRL (11 of them) was missing from its `STANDINGS_STATS` map, so the League Overview table silently had no W/L columns for any of them. Fixed for all of them at once, not just IPL/BBL.

Checked and NOT viable:
- **MLS** — real team/logo data, but its `/standings` endpoint returned a genuinely empty response (`{}`, no `fullViewLink` wrapper even) — a different failure from every other league's "empty right now" shape. Re-verify directly before retrying.
- **AFLW** — no separate league exists in ESPN's API at all; `australian-football` only has `afl`.
- **NCAAF / NCAAB** (college football/basketball) — real data, but rosters are 130-200+ teams (FBS alone, before FCS/D-II noise like "Amherst Mammoths" showing up in the raw list). A real curation cost, not a quick config add — every other league shipped so far tops out around 20-30 teams.
- **Rugby union** — 25+ separate ESPN competitions, no single obvious "the" league.
- **F1** — has team-shaped data (constructors) but no "vs opponent" concept, doesn't fit the app's card model.
- **Other cricket formats/leagues (Test cricket, ODI internationals, non-IPL/BBL T20 leagues like PSL/CPL/MLC)** — cricketdata.org's `/series` search confirmed these exist in its data too, just not built/wired up. Extending `cricketService.js`'s `SERIES_IDS` to cover more leagues is cheap *if* the shared 100/day budget can take it — every additional cricket league adds real rate-limit pressure, unlike ESPN where adding leagues was essentially free.

**J1 League (Japan) — added 2026-09-24** as `JLEAGUE` (`soccer/jpn.1`, team IDs `jleague-{espn abbr}`). Roster of 20 taken directly from ESPN's live team list, which reflects the 2026-27 autumn–spring season (Mito HollyHock, V-Varen Nagasaki and JEF United Chiba promoted). **Belgian Pro League — added 2026-09-25** as `BELGIUM` (`soccer/bel.1`, team IDs `belgium-{espn abbr}`). 18 clubs from ESPN's live team list, cross-checked against the 2026-27 standings (exact same 18 ids). All abbreviations unique and ESPN's own; no name-substring collisions (scanned every displayName/shortDisplayName/name/location); no placeholder colours. Verified live: all 18 resolve to distinct ids with real results.

**Cross-league issues found while adding J1 (2026-09-24), NOT fixed — affect leagues already live:**
- **Standings empty for every ESPN league.** `site.api.espn.com/apis/site/v2/sports/{sport}/{league}/standings` now returns only a `fullViewLink` stub (US leagues, AFL, NRL) or bare `{}` (every soccer league) — so `ladderPosition` is null and League Overview tables are empty everywhere. The real data is at `site.api.espn.com/apis/v2/sports/{sport}/{league}/standings` (note: no `/site/`), confirmed populated for all 17 ESPN leagues checked. **This also means MLS's "empty standings" disqualification below was probably this same issue, not an MLS problem** — MLS returns 30 rows on the `apis/v2` endpoint.
- **No next fixture for soccer leagues.** ESPN's soccer `/teams/{id}/schedule` returns only past matches; upcoming ones need `?fixture=true`. NFL etc. are unaffected (their `/schedule` includes future games). Confirmed for Celtic, Fenerbahçe and every J1 club.
- **ESPN placeholder colours.** Many clubs have `color: 000000` with `alternateColor` `000000`/`C60000` — ESPN's "no data" default, not real colours. Since live ESPN colours take priority over `teamColors.js`, these render as black. Counts: J1 12/20, Turkey 11/18, Argentina 6/30, Saudi 2, Portugal 2, Ligue 1 1.

**How to apply:** if asked to add more sports later, no pre-verified league is waiting — start with the checks used for J1/Belgium (live roster vs current standings, abbreviation + name-substring collision scan, per-team schedule, live smoke test). For more cricket leagues, check the shared 100/day budget can take it before adding to `SERIES_IDS`. Skip re-probing MLS/rugby-union/F1/AFLW/college sports from scratch — see above for why each didn't make the cut.
